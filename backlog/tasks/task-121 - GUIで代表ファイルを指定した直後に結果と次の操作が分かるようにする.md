## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
「サムネイル自動生成元に設定」を実行しても今ある葉は変わらず、マップにも変化が出ないため、失敗したように見える。実際のプロジェクトでも、サムネイル自動生成元の指定は成功しているのに、保存も既存の葉への適用も行われていなかった。適用の操作はファイルパネルに小さく出るだけで、流れの中で案内されない。「サムネイル自動生成元に設定」は画像以外の行にも表示され、その分パス名も短く省略される。登録済みのサムネイルが変わらないことも画面から分からない。
用語はTASK-125.12で確定した「サムネイル自動生成元」にそろえる。このタスクの既存の機能範囲は維持する。
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 サムネイル自動生成元の指定後に、サムネイルのない葉があれば件数を示して、それらの葉へ適用するかを確認する。適用しない場合はサムネイル自動生成元の指定だけが残る
- [ ] #2 サムネイルのない葉がない場合は確認を出さず、次の保存から適用されることを通知で案内する
- [ ] #3 通知とパネルから、登録済みのサムネイルは変わらないことと、次の保存から自動で作られることが分かる
- [ ] #4 「サムネイル自動生成元に設定」は対応する形式の画像の行にだけ表示される。指定済みのファイルが対応外になった場合は理由が分かり、解除できる
- [ ] #5 適用後はマップに新しいサムネイルが表示される
- [ ] #6 自動テストで確認、適用しない場合、対象の葉がない場合、画像以外の行の表示を検証し、実際のCLIにつないだ画面でも確認して、gui/README.mdを更新する
<!-- AC:END -->
