## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
制作途中のスナップショットが蓄積したリポジトリの使用容量を削減できるよう、不要な中間コミットを削除する prune 機能を追加する。指定したタグ間を対象にするモードと、全履歴からタグ付きコミットおよび現在存在する各ブランチの先端だけを保護して、それ以外を削除する一括モードを提供する。削除後は各保護コミットの親を元の履歴上で最も近い保護祖先へ接続し、コミットID、タグ、ブランチ先端、保存済みファイル内容を維持する。削除済みブランチ由来のタグなしコミットと、タグもブランチ参照もない履歴末端は保護しない。削除されたコミットだけが参照していたオブジェクトは既存の gc で回収できるようにし、SQLiteデータベースのVACUUMやファイルサイズ縮小は対象外とする。
<!-- SECTION:DESCRIPTION:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. PruneResultと履歴選択ロジックを追加し、タグ間モードでは終了タグから開始タグへの祖先経路内、全履歴モードでは全コミットから、全タグおよび現存ブランチ先端を除いた削除候補を決定する。 2. すべての残存コミットを最寄りの残存祖先へ再接続し、候補コミットの削除を単一SQLiteトランザクションで実行する。実行前に削除対象と一致する復元済み作業ツリーを拒否し、失敗時は全変更をロールバックする。 3. 削除後に未参照となる実在オブジェクト数・圧縮後容量を算出し、dry-runではDBを変更せず同じ結果を返す。 4. CLIへprune START_TAG END_TAG / prune --all、--dry-run、不可逆な実行用--yes、構造化JSON結果を追加し、排他的・不足・祖先順序エラーを明確化する。 5. 直線履歴、途中タグ、複数ブランチ、削除済みブランチ、dry-run、作業ツリー保護、トランザクション失敗、gc・添付参照連携を自動テストし、READMEへ操作方法と制限を記載する。
<!-- SECTION:PLAN:END -->
