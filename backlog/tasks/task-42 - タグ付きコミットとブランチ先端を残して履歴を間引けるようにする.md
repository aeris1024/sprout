## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
制作途中のスナップショットが蓄積したリポジトリの使用容量を削減できるよう、不要な中間コミットを削除する prune 機能を追加する。指定したタグ間を対象にするモードと、全履歴からタグ付きコミットおよび現在存在する各ブランチの先端だけを保護して、それ以外を削除する一括モードを提供する。削除後は各保護コミットの親を元の履歴上で最も近い保護祖先へ接続し、コミットID、タグ、ブランチ先端、保存済みファイル内容を維持する。削除済みブランチ由来のタグなしコミットと、タグもブランチ参照もない履歴末端は保護しない。削除されたコミットだけが参照していたオブジェクトは既存の gc で回収できるようにし、SQLiteデータベースのVACUUMやファイルサイズ縮小は対象外とする。
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 2つのタグを指定すると、両端を含むタグ付きコミットと現存ブランチ先端を保護しながら、対象区間内のタグなし中間コミットを削除できる
- [ ] #2 全履歴を対象にするオプションでは、すべてのタグ付きコミットと現在存在する各ブランチの先端を残し、それ以外のコミットを削除できる
- [ ] #3 削除済みブランチ由来のタグなしコミット、およびタグもブランチ参照もない履歴末端は一括削除の保護対象にならない
- [ ] #4 削除後、各保護コミットの親は元の履歴上で最も近い保護祖先になり、logで履歴を途切れずに辿れる
- [ ] #5 保護されたコミットのID、タグ、ブランチ先端、メッセージ、日時および保存済みファイル内容は変更されない
- [ ] #6 dry-runで削除予定のコミット一覧、件数、解放可能になるオブジェクト数と容量を確認でき、リポジトリは変更されない
- [ ] #7 削除後に既存のgcを実行すると、削除コミットだけが参照していたオブジェクトが回収され、残存コミットまたは将来の添付機能から参照されるオブジェクトは保持される
- [ ] #8 作業ツリーが削除対象のタグなし過去コミットと一致し、現在のブランチ先端とは異なる場合は処理を拒否し、タグ付けまたはブランチ作成を案内する
- [ ] #9 タグ指定の順序が祖先関係になっていない場合、参照が解決できない場合、または排他的なオプションを同時指定した場合は、履歴を変更せず明確なエラーを返す
- [ ] #10 処理が失敗した場合はコミット、親子関係、タグ、ブランチ参照の変更が残らない
- [ ] #11 CLIヘルプとREADMEにタグ間モード、一括モード、dry-run、gcとの役割分担、保護対象および削除が取り消せないことが記載される
- [ ] #12 タグ間の直線履歴、途中タグ、複数ブランチ、削除済みブランチ、dry-run、作業ツリー保護、エラー時の非変更、gc連携が自動テストで検証される
