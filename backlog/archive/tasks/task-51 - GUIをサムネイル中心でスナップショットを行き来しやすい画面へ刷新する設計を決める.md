## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
## 背景

現在のGUI（gui/）はステータス・ツリー・コミット・履歴・ブランチの5タブ構成で、保存と過去スナップショットへの移動が別々のタブに分かれている。過去の状態へ戻るにはツリータブでノードを選び、詳細欄の復元ボタンと確認ダイアログを経る必要があり、気軽に行き来できない。コミットツリーはインデント付きの親子リスト表示で、サムネイルが主役になっていない。また操作のたびにCLIを複数回起動して画面全体を再取得している。

## ゴール

Sproutらしいサムネイル中心の表示と、スナップショット間を簡単に行き来できる操作を軸に、GUIの画面構成・見た目・操作フローを刷新する設計を決める。現在のツリー構造表示は廃止する前提とする。本タスクは設計の確定と後続実装タスクへの分割までを範囲とし、GUIの本実装は含めない。

## 決めること

- スナップショットの一覧・俯瞰の表示形式（サムネイルの見せ方、分岐・ブランチ・タグの表現、サムネイルがないスナップショットの扱い）
- スナップショット間を移動する操作と、未保存の変更があるときの扱い
- 保存（コミット）・追跡・ブランチなど既存機能の新しい配置と、タブ構成の見直し
- 見た目の方向性（配色、レイアウト、ライト/ダーク）
- 必要なCLI側の追加・変更と、応答速度の目標（serve常駐モードTASK-26の要否を含む）

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
## 決定済み（2026-10-27 ユーザー合意）

### 表示形式: 芽のマップ（縦向き）
- 古いスナップショットを下（根元）、新しいものを上（先端）に置き、茎が下から上へ伸びる。
- メインの茎の左右へスナップショットを葉として交互に付ける。サムネイルがない葉は同じ大きさの無地で表示する。
- 分岐したブランチは茎の途中から横へ分かれ、同じく上へ伸びる。ブランチ名は枝の先、タグは葉の札で示す。
- 現在の位置を青い枠で示し、未保存の変更は今いる芽の横に点線の芽として出す。保存すると芽が葉になる。
- 葉を選ぶと右側に詳細を出し、「ここへ移動」「ここから枝を伸ばす」「サムネイルを変更」「ファイルを取り出す」を置く。
- 5タブ構成は廃止して1画面にまとめる。追跡ファイル管理は上部バーの「ファイル」パネル、CLI設定は歯車へ移す。
- 開いた直後は先端（現在位置と未保存の芽）が見える位置へスクロールする。件数が多い場合のズームや古い区間の折りたたみを検討する。

### 未保存の変更: つぼみとして自動退避
- 未保存の変更があるまま別の芽へ移ると、確認なしで追跡ファイルの状態を「つぼみ」として退避し、移動前にいた芽の横に付ける。
- つぼみを選ぶと作業ツリーを退避時の状態へ戻し、現在位置をその芽にする。戻したつぼみは書き戻し完了後に消す。
- 1つの芽に複数のつぼみを付けられる。手動で捨てるときは確認する。
- つぼみの実体は既存objectsストアへ保存して重複排除を共有し、gc・doctor・statsが参照を考慮する。
- 未追跡ファイルは削除・上書きせず、移動先と衝突する場合は中止する現行の保護を維持する。

### 途中の芽からの保存: 自動で枝を作る
- 現在位置がブランチ先端以外の芽のときに保存すると、その芽を起点に新しいブランチを自動作成し、そこへ葉を付ける。ブランチ名は自動で付け、後から変更できる。

### 判明した現行CLIの制約
- restoreは作業ツリーを書き戻すだけで現在位置を記録せず、commitは常にブランチ先端を親にする（src/sprout/repository.py の restore と commit）。現在位置はファイル内容の一致から推測するしかない。
- そのためCLIに「現在位置の記録」「つぼみの作成・一覧・復元・破棄」「退避と移動を一括で安全に行う移動操作」「途中の芽からの保存時の自動ブランチ作成」が必要。保存形式は正式リリース前のVersion 1のまま拡張し、移行処理は設けない。

## 切り替え時間の計測（2026-10-27）
条件: Windows 11、.venvのsprout 0.1.0、追跡ファイル20件（各2 MB、計40 MB）、コミット30件。現在のGUIが復元時に呼ぶコマンドを個別に計測した中央値。
- プロセス起動のみ（--version）: 232 ms
- restore: 1173 ms
- status --tracked --untracked: 433 ms
- log: 270 ms / branch: 303 ms / tree: 365 ms
- 直列合計: 2531 ms。GUIはlog・branch・treeを並列実行するため体感は約2.0秒。
所見: 1回の切り替えでCLIを5回起動しており、起動だけで約1秒かかる。restore自体も未保存変更の判定で追跡ファイル全体をハッシュするため重い。

## 応答速度の方針（2026-10-27 ユーザー合意）
- 新しい移動コマンドは、退避・移動に加えて移動後の現在位置・変更有無などGUIが必要とする状態をまとめて返し、1回の移動でCLI呼び出しを1回にする。
- TASK-26（serve常駐モード）は新GUIの実装より前に行う。
- 追跡ファイルのハッシュ計算をサイズ・更新日時の記録で省略する高速化は独立した改善タスクにする。
- 目標: 一般的な規模のプロジェクトで芽の移動を1秒以内に完了し、GUIはクリック直後に選択表示を更新する。

## 見た目と機能配置（2026-10-27）
- 見た目はA案「植物ノート」（生成りの紙と緑のインク、ライト/ダーク両対応でOS設定に追従）。ユーザーが後で変更したくなる可能性が高いため、色・角丸・余白をテーマ用のCSS変数に集約し、コンポーネントへ色を直書きしない。
- 機能配置案: 左サイドバーとタブを廃止。最近使ったプロジェクトは上部バーのプロジェクト名から開く一覧と未選択時の初期画面、初期化は未初期化フォルダ画面、CLI設定は歯車、変更一覧とコミット作成は未保存の芽の詳細パネル（上部バーの保存ボタンとCtrl+Sからも開く）、追跡管理は上部バーのファイルパネル（ウィンドウへのドロップで追跡は維持）、サムネイル登録とメッセージ編集は葉の詳細、復元は「ここへ移動」、ブランチ作成は「ここから枝を伸ばす」、ブランチ切り替えは枝先の葉かブランチ名。履歴タブとステータス件数表示は廃止。
- メモ・ラベル・タグの編集とブランチのリネーム・削除は新GUI初版に含めず後続とする。
