# Sprout GUI

Sprout GUIは、Tauri 2、React、TypeScript、Viteで構築したWindows向けデスクトップアプリです。
GUIは`.sprout`を直接操作せず、Rust側の共通IPCコマンドから`sprout <command> --json`を実行します。

## 必要な環境

- Windows 10または11とWebView2 Runtime
- Node.js 20.19以降
- pnpm
- Rust stable（MSVC toolchain）
- Visual Studio 2022のDesktop development with C++とWindows SDK
- PATH上のSprout CLI、またはGUIの「CLI設定」で指定する実行ファイル

リポジトリのルートで`install.cmd`を実行すると、CLIのインストールとGUIのビルド・インストールをまとめて行えます。CLIだけなら`.\install.cmd -CliOnly`、インストーラーの作成までなら`.\install.cmd -BuildOnly`です。詳しくはルートの[README.md](../README.md#まとめてインストールwindows)を参照してください。

CLIだけを手動でインストールする場合は、リポジトリのルートで次を実行します。

```powershell
uv tool install .
sprout --help
```

Rustを初めて導入した直後は、ターミナルを再起動して`cargo`へのPATHを反映してください。

## 開発

`gui`ディレクトリで依存関係を準備し、Tauriの開発ウィンドウを起動します。

```powershell
cd gui
pnpm install
pnpm tauri dev
```

フロントエンドだけをブラウザで確認する場合は`pnpm dev`を使えます。ただし、フォルダ選択、設定保存、Sprout CLI呼び出しはTauriウィンドウ内でのみ動作します。

## 検証とビルド

```powershell
pnpm test
pnpm build
cargo test --manifest-path src-tauri/Cargo.toml
pnpm tauri build
```

`pnpm tauri build`の成果物は`gui/src-tauri/target/release/bundle/`へ作成されます。

## 初回利用

1. PATHに`sprout`がない場合は、右上の歯車からCLIの実行ファイルを指定します。
2. 「プロジェクトを選択」、または上部バーのプロジェクト名から「フォルダを開く…」で作業フォルダを選択します。
3. 未初期化のフォルダでは、確認画面から`sprout init --json`を実行できます。

## 用語

画面と通知では次の言葉を使います。`sprout`のコマンドやJSON、`.sprout`の内部では右の言葉のままです。

| 画面の言葉 | 意味 | 内部の言葉 |
| --- | --- | --- |
| 葉 | 保存した1回分の状態。「スナップショット」「コミット」とは表示しません。 | commit、snapshot |
| メッセージ | 葉に付ける説明 | commit message |
| ブランチ | 名前を付けた履歴の流れ。「枝」とは表示しません。 | branch |
| つぼみ | 退避した変更 | bud |
| 未保存の芽 | まだ葉になっていない変更。「芽」はこれと「芽のマップ」だけに使います。 | uncommitted changes |
| いまここ | 作業フォルダの現在位置 | current commit |
| プレビュー | 葉に添付したファイル | preview |

見出しや札は英語にせず、この表の言葉で表示します。ブランチ名やファイル名など、利用者が付けた名前と`Sprout CLI`などの固有名詞はそのまま表示します。

CLIのエラー文は英語のままで、GUIはエラーの`code`を[`src/lib/cliErrors.ts`](src/lib/cliErrors.ts)の対応表でこの表の言葉に置き換えて表示します。GUIから実行する操作の主なエラー（葉・ブランチ・タグ・つぼみ・メモ・ラベル・サムネイル・プレビューの指定、移動と復元の衝突、書き出し、ゴミ箱の復旧、ロック）が対象です。対応表にない`code`のエラーは、CLIの原文のまま表示します。履歴の破損など内部の不整合を示すエラー、OSやSQLiteのエラー、個別の`code`を持たない古いCLIのエラーがこれに当たります。CLIが書き出すアーカイブのHTMLも対象外です。

## 画面構成

画面は上部バー、中央の芽のマップ、右側のパネルの1画面です。マップとパネルの間の分割線をドラッグするか、フォーカスして←→（Home・Endで最小・最大）を押すとパネルの幅（280〜720px）を変更でき、ダブルクリックで元の幅に戻ります。幅は再起動後も維持します。ウィンドウが狭くなるとパネルを縮めてマップの幅を360px以上保ち、幅660px以下ではパネルをマップの下へ移します。上下に並べるときはどちらも操作できる高さを保ち、足りない分はウィンドウ全体をスクロールします。

- **上部バー**: プロジェクト名（クリックで最近使ったプロジェクトの切り替え・一覧からの削除・フォルダを開く）、現在のブランチ、保存状態（保存済み／未保存の変更の件数）、更新、ファイル、ゴミ箱、保守、保存、設定（歯車）を表示します。
- **右側のパネル**: 何も選んでいないときは未保存の変更と保存フォームを表示します。メッセージと、必要なら2 MiB以下のPNG・JPEG・WebPサムネイルを指定して保存します。サムネイルはファイルを選ぶほか、このパネルを表示中にメッセージ欄などの入力欄の外でCtrl+Vを押し、クリップボードの画像を貼り付けても指定できます（入力欄での貼り付けはテキストだけが入力され、画像ではサムネイルを変更しません）。途中の葉から保存すると新しいブランチが自動で作られます。上部バーの「保存」とCtrl+Sでこのパネルを開きます。
- **葉の詳細の並び**: 先頭にメッセージと主要な操作を置き、その下に「メモ・ラベル・タグ」「プレビュー」「保存済みファイル」への移動リンク、情報、メモ・ラベル・タグ、プレビュー、保存済みファイルの順に並べます。移動リンクはスクロールしてもパネルの上端に残ります。
- **葉の詳細**: 選んだ葉のメッセージ、日時、ブランチ、タグ、添付、ファイル数を表示し、「ここへ移動」「ブランチを作る」「サムネイルを登録・変更」「メッセージを編集」「ファイルを取り出す」を行えます。サムネイル登録・変更、ファイル取り出し、葉の削除は「その他の操作」メニューにまとめています。「ここへ移動」「ブランチを作る」「比較元にする」は直接使えます。メニューはEnter・Space・↓で開き、↑↓・Home・Endで項目を選び、Enter・Spaceで実行できます。Escはメニューだけを閉じて入口へフォーカスを戻し、入力中の内容は残します。Tabで外へ移動したときやメニューの外を押したときも閉じます。葉やプロジェクトの切り替え・操作開始時にはメニューを閉じます。葉の詳細を表示中に入力欄の外でCtrl+Vを押してクリップボードの画像を貼り付けると、その葉のサムネイルとして登録します。すでにサムネイルがある場合は置き換えの確認を表示し、キャンセルすると変更しません。ゴミ箱・比較・ファイルパネル・CLI設定を表示中は、画像を貼り付けても葉を変更しません。「ここへ移動」は確認なしで`sprout go`を実行し、未保存の変更は移動前の葉のつぼみとして残ります。移動後の現在位置・ブランチ・つぼみは1回の応答でマップと上部バーへ反映します。「ブランチを作る」は名前を付けたブランチを作ってその葉へ移ります。「この葉を削除」は`sprout delete-commit --dry-run`で影響（親へ移るブランチ・いまここ、つなぎ直す子の葉、付け替えるつぼみ、ゴミ箱へ保持する容量）を確認ダイアログに表示し、「削除」を選んだときだけ削除します。キャンセルすると何も変更しません。作業ファイルは変わらず、削除した葉との差分は未保存の変更として残ります。タグ付きの葉は削除できず、メニュー内に理由を表示します。
- **メモ・ラベル・タグ**: 葉の詳細の情報の下で編集します。メモは「メモを書く／メモを編集」から保存し、空にして保存するとゴミ箱へ移します（20,000文字まで）。ラベルは入力して「追加」、チップの×で外します（1件64文字・1つの葉に32件まで）。タグはコメント付きで一覧し、名前とコメントを入力して「タグを付ける」、各タグの「編集」でコメントを変更、「削除」は確認後にタグだけを消し、タグはゴミ箱から戻せます。CLIに拒否された場合は理由を通知し、入力内容はそのまま残ります。編集後はマップと詳細を取り直します。
- **葉の読み込み失敗**: 葉の詳細を読み込めなかった場合は、理由と「再試行」をパネルに表示します。別の葉を選ぶか閉じると元に戻ります。
- **ブランチの詳細**: 芽のマップのブランチ名、または上部バーの現在のブランチをクリックすると開きます。名前・作成日時・コメント・先端の葉（クリックでその葉を開く）を表示し、名前の変更とコメントの編集（空にして保存すると消える）ができます。「ブランチを削除」は確認後に実行し（ゴミ箱から戻せます）、そのブランチの葉は「削除済みブランチ由来」として残ります。現在のブランチは削除できません。名前を変えても同じブランチとして選択したままになり、CLIに拒否された場合は入力内容が残ります。
- **ブランチの表示**: ブランチはIDで識別します。葉やつぼみの詳細では、作成時から名前が変わったブランチを「現在の名前（作成時: 元の名前）」、削除されたブランチを「名前（削除済み）」と削除日時付きで表示するため、同じ名前で作り直したブランチと混同しません。現在位置はCLIが記録した位置だけを使い、ブランチ先端から推測しません。
- **添付**: 葉の詳細に、サムネイルとプレビューを保存された表示順で、種類・元のファイル名・形式・サイズとともに一覧します。プレビューは専用パネルから追加・置き換え・削除・並べ替え・取り出しできます。
- **つぼみ**: 退避した変更は元の葉の下に「つぼみ N」として表示されます。最初の保存より前に退避したつぼみは地面の「はじまり」の横に並び、葉がまだない場合はマップの中央に一覧されます。削除済みブランチで退避したつぼみは、戻しても今のブランチのままです。「名前を付ける」で名前を付けるとマップにも表示します（長い名前は省略し、ポインタを重ねると全体を表示）。選ぶと変更ファイルを確認でき、「このつぼみに戻る」で作業フォルダをその状態へ戻します（今の未保存の変更は新しいつぼみとして残ります）。「つぼみを捨てる」だけは確認が表示され、捨てたつぼみはゴミ箱に残ります。
- **未保存の芽**: 未保存の変更があると、現在位置の葉の右に「未保存の芽」が出ます（途中の葉にいるときは別の行へ分かれます）。選ぶと変更ファイルと保存フォームを表示します。途中の葉から保存する場合は、新しいブランチが自動で作られることを保存前に表示します。「つぼみとして残す」は`sprout bud --save`を実行し、移動せずに今の未保存の変更をつぼみへ移し、作業フォルダを今の葉の内容に戻します（未保存の変更がないときは押せません）。未保存の芽は消えてつぼみがマップに加わるので、その後に移動してもつぼみは増えません。追跡中の追加ファイルは作業フォルダから消えてつぼみに入り、未追跡ファイルは変わりません。「このつぼみに戻る」で元の状態に戻せ、「つぼみを捨てる」で変更ごと手放せます。失敗時や、更新前に変更がなくなっていた場合は理由を通知して、作業ファイルとつぼみを変更しません。
- **未保存の変更のファイルごとの操作**: 変更一覧の各行から1ファイルずつ戻せます。変更・削除は「元に戻す」で現在位置の葉の内容へ置き換えます（`sprout restore <現在位置> <ファイル> --discard`）。確認ダイアログに対象と、変更内容が失われること、破棄した内容がゴミ箱からつぼみとして戻せることを表示し、キャンセルすると何も変更しません。追加は「追跡から外す」で追跡対象から外し（`sprout untrack`）、ファイル自体は削除せず未保存の変更からだけ外します。改名は2つのパスにまたがるため、この操作は表示しません。実行後は未保存の変更・上部バー・マップを更新し、失敗時は理由を通知して作業フォルダを変更しません。
- 移動やつぼみの復元が未追跡ファイルとの衝突などで中止された場合は、理由と対象のパス、作業フォルダを変更していないことを通知します。
- **大文字小文字だけの改名**: エクスプローラーなどで大文字小文字や表記だけを変えたファイルは、未保存の変更に「改名」と元の表記付きで表示され、保存すると同じ素材のまま新しい表記を記録します。比較結果も同様に表示します。
- **代表ファイル**: ファイルパネルで追跡中の画像を「代表にする」と、サムネイルを指定せずに保存したときに、そこからサムネイルを自動で作ります。作れなかった場合も保存は成功し、理由を通知します。「既存の葉へ適用」はサムネイルのない葉にだけ、確認後に作ります。
- **ファイルパネル**: 上部バーの「ファイル」で開き、追跡中・未追跡のファイル一覧、追跡と追跡解除を行います。ウィンドウへファイルやフォルダをドロップしても追跡できます。長いパスは行内で「…」に省略し、ポインタを重ねると全体を表示します。「追跡解除」「追跡する」は横スクロールなしで押せます。「追跡解除」は作業ファイルを削除しません。
- **葉の情報と検索**: 葉にポインタを重ねるかキーボードでフォーカスすると、メッセージの全文と日時を表示します。メモやラベルがある葉には目印を付けます。「葉を検索」でメッセージ・タグ・ラベルを絞り込むと、該当しない葉が薄くなります。Enter（Shift+Enterで逆順）か↑↓で該当する葉へ移動して選択します。Escか×で解除します。検索は履歴と作業ファイルを変更しません。
- **マップの移動**: 縦にスクロールできないときは通常のホイールで横に動きます（Shift+ホイールも使えます）。背景をドラッグしても移動でき、倍率を変えても見ていた場所を保ちます。「いまここへ戻る」で現在位置へ戻れます。
- **芽のマップ**: 削除済みブランチ由来を含む全ての葉を、古いものが左・新しいものが右になるよう、横に伸びる茎と葉で表示します。ブランチごとに茎の行があり、分岐元の葉から分かれて右へ伸びます。葉は茎の節の上に付き、サムネイルとメッセージを表示します（サムネイルがない葉は「画像なし」）。ブランチ名は茎の右端、タグは葉の左上の札で示し（葉に収まらない長いタグ名は「…」で省略し、札にポインタを重ねると全体を表示）、現在のブランチを強調します。現在位置は青い枠と右上の「いまここ」札で示し（タグ札に重なる場合は葉の上へずらします）、開いた直後や更新後は現在位置が見える位置へスクロールします。左上のボタンで50〜150%に拡大・縮小できます。葉・つぼみ・ブランチ名はクリックまたはキーボード（Tab、Enter）で選択できます。同じ葉が複数のブランチの先端なら、ブランチ名は縦に並びます。まだ保存のないブランチのように、茎の途中の葉が先端のブランチは、節の下から線でつないだ先に名前を表示し、茎と重ならないようにします（名前が長い場合はマップの左右に余白を取ります）。

ブランチ切り替えまたは復元が未保存変更によって拒否された場合だけ、追跡対象の変更を破棄して再実行する確認画面が表示されます。破棄した変更はゴミ箱に残ります。操作中は他の操作ボタンが無効になります。

状態は「更新」のほか、別のアプリからウィンドウへ戻ったときにも自動で再取得し、未保存の変更、追跡状態、上部バー、マップを最新にします。自動の再取得はボタンを無効にせず、表示中の通知、選択中の葉、入力中のメッセージやメモ、マップのスクロール位置を保ちます（別の場所で新しい葉を保存した場合や現在位置が変わった場合は、現在位置へスクロールします）。他の操作の実行中は行わず、再取得中に操作を始めるとその結果を優先します。フォーカスが短時間に繰り返し変わっても、再取得は2秒に1回までです。ロックなどで再取得できないときは、通知がなければ警告を1回だけ表示し、次に成功すると消します。ファイルの常時監視は行いません。

見た目はライトの配色「朝霧」（Morning mist）とダークの配色「夜霧」（Night mist）で、どちらになるかはOSの設定に従います。色・角丸・余白・フォントは`src/App.css`冒頭のCSS変数に集約しているため、配色を変える場合はそこだけを差し替えます。ボタンは共通の見た目を使い、枠線の赤はゴミ箱から戻せる削除、塗りつぶしの赤は完全削除のように取り消せない操作を示します。

貼り付けた画像はOSの一時フォルダへ`clipboard.png`などの名前で書き出してから`sprout`へ渡し、登録後や解除・差し替え時に削除します。PNG・JPEG・WebP以外や2 MiBを超える画像は登録せず警告を表示します。

サムネイルはPNG・JPEG・WebPだけを画面内へ近づいた時点で読み込みます。取得結果はプロジェクト、葉のID、オブジェクトハッシュ、メディアタイプ単位でメモリへキャッシュされます。音声、動画、アニメーション画像、3Dモデルは自動再生・描画しません。

最近使ったプロジェクトとCLIパスは、Tauri StoreによりOSのアプリデータ領域へ保存されます。最近使った一覧の削除ボタンは保存された一覧だけを更新し、プロジェクトのフォルダーやSprout履歴、現在開いている画面を削除・終了しません。
Sprout CLIがロック中の場合は再試行ボタンを表示し、CLIが見つからない場合はCLI設定を開きます。

GUIはPATHまたは手動指定のCLIを`sprout serve`として1つだけ常駐させ、すべての操作をその常駐プロセスへJSON Linesで送ります。CLIの切り替え時は常駐プロセスを起動し直します。`serve`に対応していない古いCLIでは、従来どおり操作ごとにCLIを起動します。常駐プロセスが途中で終了した場合は、その操作を都度起動で実行し、次の操作で常駐プロセスを起動し直します。将来sidecarを同梱する場合も、Rust側の実行ファイル解決だけを差し替え、フロントエンドのIPC契約は維持します。

### 葉の比較

葉を選び、詳細の「比較元にする」を押してから、マップで比較先の葉を選びます。比較元・比較先は選択欄でも変更できます。「比較する」で、比較元から比較先への追加・変更・削除ファイルとサイズを表示します。差分なしの場合も表示します。失敗した場合は理由を確認し、同じボタンで再試行できます。比較は作業ファイルや現在位置を変更しません。本文や画像内容の比較は対象外です。

### ファイルを選んで取り出す・戻す

葉の詳細の「保存済みファイル」でパスとサイズを確認し、チェックボックスでファイルを選択します。フォルダの「配下を選択」や「すべて選択」も使えます。「選択したファイルを取り出す」は指定した出力先へ相対パス構造と保存時の更新日時を保って書き出し、作業フォルダを変更しません。既存ファイルへの上書きは行いません。

「選択したファイルだけ戻す」は対象と影響の確認後、作業フォルダ内の同じパスへ部分復元します。選択外のファイル、現在位置、ブランチ先端は変わりません。対象に未保存変更があれば、破棄して戻すかを改めて確認します。キャンセルすると変更しません。未追跡ファイルの衝突やリンクなどでCLIが拒否した場合は、通知に理由と対象パスを表示します。別の葉を開くと選択はリセットされます。

### プレビューを管理する

葉の詳細の「プレビューを追加」で任意形式のファイルを複数選択できます。葉の詳細を表示中にファイルをウィンドウへドロップしても追加できます。ドロップ先は表示中のパネルで決まり、ファイルをウィンドウに重ねている間は画面上部に追加先を表示します。葉の詳細ではその葉のプレビュー、ファイルパネル・保存フォーム・ブランチ・つぼみの表示中は追跡対象へ追加し、ゴミ箱・比較・CLI設定の表示中は何も追加しません。「プレビュー貼り付け領域」をクリックして Ctrl+V を押すと、クリップボードに含まれる画像・ファイルをプレビューとして追加します。この領域の外の画像貼り付けは、従来どおりサムネイルの登録です。

各プレビューは保存された順番で元ファイル名・形式・サイズを表示します。「置き換え」「削除」「取り出す」と上下ボタンで個別に管理できます。並べ替えはその都度保存され、再読み込み後も維持されます。「取り出す」で既存ファイルを無断で上書きしません。100 MiB を超えるファイルはサイズと圧縮前の最大追加容量を確認した後だけ登録します。失敗時は通知に理由を表示し、既存のプレビューや順序を保ちます。音声・動画・3Dモデルの再生や表示は別機能です。

### 静止画像のプレビュー表示

葉の詳細のプレビュー一覧で「画像を表示」を押すと、その画像をGUI内で確認できます。PNG・JPEG・静止WebP・BMPに対応し、画像以外のプレビューは従来どおり取り出して確認できます。画像は選択したときだけ読み込み、別の画像への切り替えや「画像表示を閉じる」で表示を終了します。別の葉・プロジェクトへの移動や画像の置き換え・削除でも古い表示を残しません。

GUIの表示上限は原本20 MiB、一辺8192px、1600万画素です。表示用の画像は長辺2048px以内に縮小し、元の寸法と縮小表示である旨を示します。原本・作業ファイルは変更しません。破損・未対応・アニメーション・上限超過の場合は理由を表示します。「画像を再読み込み」または一覧の「取り出す」を利用してください。


### 保守

上部バーの「保守」で、葉・ブランチ・追跡パス・つぼみ・オブジェクトの件数と、論理容量・実容量・重複排除の節約量を確認できます。

「回収できる容量を確認」は回収対象のオブジェクト数・一時ファイル数・容量を確認ダイアログに表示し、「回収」を選んだときだけ`sprout gc`を実行します。ゴミ箱に保持中のデータは回収しません。回収するには先にゴミ箱で完全削除してください。

「検査する」は`sprout doctor --report`を実行します。問題がなければ検査したオブジェクト数を、問題があれば種類と詳細を表示します。問題の検出は操作の失敗とは区別して、検査結果としてこのパネルに表示します。

### ゴミ箱

上部バーの「ゴミ箱」で削除した葉・プレビューと置き換え前のプレビュー、捨てたつぼみ、破棄した未保存の変更、削除したメモ・タグ・ブランチを一覧します。日時はローカル時刻で表示し、内部IDは各項目の「内部ID」を開くと確認できます。捨てたつぼみと破棄した変更は、復旧するとつぼみとして戻ります。「復旧内容を確認」で元のファイルや添付、戻す参照を確認でき、各項目に保持容量と完全削除後の回収可能容量を表示します。共有分を含むため、保持容量の単純な合計はプロジェクト全体の容量とは一致しません。

「復旧」は事前に競合と実体を検査し、確認後に復旧します。作業ファイルは変更しません。影響する参照やプレビュー一覧が変わっていた場合は理由を表示し、復旧項目を残します。複数回の置き換えは新しい項目から順に戻してください。「完全削除」は対象IDと回収可能容量を表示して確認を求めます。完全削除した項目は戻せず、実体は「保守」の容量の回収（gc）で回収します。

ゴミ箱の自動削除はありません。pruneは取り消し対象外、archiveもゴミ箱を含まないため、復旧データのバックアップにはプロジェクト全体のコピーを使ってください。


### プレビューのメタ情報

プレビューは葉全体を確認するための添付資料です。追跡対象外のファイルも添付でき、各プレビューの「表示名・説明を編集」から表示名と説明を保存できます。空の表示名は元のファイル名を表示します。重要な資料は上へ並べ替えられ、順序を変えてもメディアを読み込まず、サムネイルも変更しません。内容を置き換えても添付ID・表示位置・最初の登録日時と設定を保持します。削除や置き換えをゴミ箱から戻すと設定も復旧し、その後にメタ情報や添付一覧を変更していた場合は競合として拒否します。CLIの正規入口は`leaf preview`です。


### 静止画像のキャッシュと清掃

選択した静止画像は、表示用PNGと原本の形式・寸法をプロジェクトの`.sprout/preview-cache/`へ保存して再利用します。完成したキャッシュの上限は256 MiBで、古い利用分から破棄します。原本や表示条件が変わった場合、キャッシュが消えたり破損した場合は作り直します。保存に失敗しても通常の画像生成で表示し、未選択画像の自動読み込みは行いません。

このキャッシュは再生成可能な補助データです。GUIとCLIを終了してから`.sprout/preview-cache/`を削除すると清掃できます。表示用キャッシュがないバックアップからも、画像を選べば再生成して閲覧できます。原本のobjectsやゴミ箱はそれぞれ独立して保持します。
